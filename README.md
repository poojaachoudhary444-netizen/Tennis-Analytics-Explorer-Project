# 🎾 Game Analytics: Unlocking Tennis Data with SportRadar API

End-to-end data project: **SportRadar API → Python (JSON parsing) → SQL database → 20 SQL analysis queries → interactive Streamlit app.**

Prepared by: **Pooja**


> ### ⚠️ Data note (please read)
> The SportRadar sign-up portal could not be reached while this project was prepared, so **no API key was available** and no real data was downloaded.
> The database in this submission is filled with **simulated sample data** that has *exactly the same JSON structure* as the real API responses (generated by `demo_data.py`).
> Everything else is complete and tested: API client, JSON parsing, SQL schema, the 20 queries, the Streamlit app and the report generator.
> **To use real data:** put a key in `.env`, then run `python run_pipeline.py --source api --reset` - nothing else needs to change.
> **To run without a key:** `python run_pipeline.py --source demo --reset`, then `streamlit run app.py` (the app shows a DEMO DATA banner).

## 2. Setup (about 10 minutes)

**Requirements:** Python 3.9+ and (optional) MySQL or PostgreSQL. SQLite works out of the box.

```bash
pip install -r requirements.txt --upgrade
```

### 2.1 Get a SportRadar API key
1. Sign up at <https://console.sportradar.com/signup> and create a **Tennis v3 trial** key.
2. Copy `.env.example` to `.env` and paste the key:
   ```
   SPORTRADAR_API_KEY=your_real_key
   ```
   `.env` is git-ignored – **never upload your key to GitHub.**

### 2.2 Choose the database
Default is SQLite (`DATABASE_URL=sqlite:///tennis.db`). For MySQL:
```sql
CREATE DATABASE tennis_db CHARACTER SET utf8mb4;
CREATE USER 'tennis_user'@'localhost' IDENTIFIED BY 'your_password';
GRANT ALL ON tennis_db.* TO 'tennis_user'@'localhost';
```
then in `.env`:
```
DATABASE_URL=mysql+pymysql://tennis_user:your_password@localhost:3306/tennis_db
```
(The tables are created automatically; `sql/schema_mysql.sql` shows exactly what is created.)

### 2.3 Load the real data
```bash
python run_pipeline.py --source api --reset
```
It calls the three endpoints (competitions, complexes, doubles rankings), saves the raw JSON in `data/raw/`, parses it, loads SQL and prints a summary (received / kept / skipped rows, defaults used, row counts, integrity checks).
Re-load later without using API calls: `python run_pipeline.py --source json`.

### 2.4 Start the app
```bash
streamlit run app.py
```

> **No API key yet?** `python run_pipeline.py --source demo --reset` loads **fictional** sample data in the real API format so you can try the app. The app shows a red **DEMO DATA** banner while it is loaded. Never submit demo data as your project data.

## 4. Database design

Tables: `categories`, `competitions` (→ categories), `complexes`, `venues` (→ complexes), `competitors`, `competitor_rankings` (→ competitors). Column names, types, primary keys, foreign keys and NOT NULL rules follow the brief exactly.

Additive extras (documented in `db.py`): `ranking_type / year / week / gender` on `competitor_rankings` (needed for the Year/Week/Gender filters), a UNIQUE snapshot key, indexes on all foreign keys and filter columns, and a small `pipeline_runs` audit table.

> **MySQL 8 note:** `rank` is a reserved word there. The schema quotes it automatically and every query writes `r.rank` (table-qualified), which MySQL always accepts.

Upload **all code files + `sql/sql_queries.sql`**. Do **not** upload `.env` (your API key) – `.gitignore` already excludes it.

*Easiest, folder-safe method – GitHub Desktop:* File → Add local repository → choose `TennisAnalytics` → Commit → Publish repository.

## 8. Optional: deploy on Streamlit Community Cloud
The app needs a database it can reach. Either use a hosted MySQL/PostgreSQL and add `DATABASE_URL = "..."` under the app's **Secrets**, or (simplest for a demo) remove `tennis.db` from `.gitignore`, commit the SQLite file that holds your **real** data, and deploy `app.py`.
